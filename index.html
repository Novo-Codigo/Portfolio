Nix

Electoral campaign management (SaaS on Android, iOS, and web).

  • Play Store
  • App Store
  • Web
  • Payments APIs

The Problem

Political campaigns were managing grassroots leadership, votes, and campaign expenses using paper and spreadsheets. Nix centralizes everything into an Android/iOS app and web platform, with subscription-based billing.

My Role

Tech lead of a 4-person team: myself and 3 interns (1 frontend, 2 backend). The product owner defined requirements and design.

Architecture & Decisions

  • Defined the stack, data model (22 models), security, compliance and data privacy (LGPD) for users and registered voters, and third-party integrations (Firebase, payments, AI, maps).
  • Implementation and delivery: developed core parts of the frontend and backend, orchestrated deployments to Render, Google Play Store, and Apple App Store.
  • Team leadership: every PR required my review before merging into development. Tasks were scoped using T-shirt sizing and balanced across individual goals. Without budget for specialized tooling, sprint tracking was maintained in spreadsheets.
  • Delivery timeline: executive management set an aggressive 1-month timeline prior to finalized scoping. The sizing breakdown showed delivery would take longer, which I communicated upfront. At the end of month one, I delivered the scoped features with full justification. Final polish and rollout extended through month seven.

Technical Decisions

Logical multi-tenancy via root_user

A single database instance. The root entity (candidate) holds full permissions over child users (staff and campaign leaders) and data within their scope. Every queryset is scoped to the candidate, and cross-tenant requests return 404 rather than 403 to prevent ID enumeration.

Cost: Isolation integrity depends strictly on proper queryset scoping across every endpoint.

Device concurrency limits per account

Each account is restricted to a maximum of one mobile and one desktop session. A subsequent login terminates previous active sessions and triggers an alert email. The device_id is encoded in the JWT and validated by the backend, preventing shared credential abuse.

Daily AI cost ceiling per user

Google Gemini powers the campaign AI assistant. Consumption cost is computed per token and aggregated. Gemini enforces hard monthly quotas, while Nix limits daily user consumption. Upon hitting the threshold, users receive notices indicating cooldown periods or token recharge options.

Subscription billing with Mercado Pago and webhooks

Checkout and billing occur via Mercado Pago. Webhook callbacks dispatch events to the API to update subscription state. Access control authorization resides strictly on the backend.

Universal codebase with Expo and React Native Web

Single shared business logic across Android, iOS, and web, making maintenance sustainable for a lean engineering team.

Axios token refresh queue

With concurrent HTTP requests and an expired access token, only the first request dispatches a refresh while subsequent requests queue and reuse the newly minted token.

Result

Product launched on Android, iOS, and web with live recurring billing in production. Did not achieve commercial scale due to go-to-market distribution limitations, outside technical scope.

Stack

  • App (iOS, Android, and web): Expo, React Native, React Native Web, TypeScript
  • Backend: Django 6, Django REST Framework, PostgreSQL, Celery, Redis
  • Integrations: Mercado Pago, Apple StoreKit, Google Gemini (campaign AI), Google Maps, Firebase (in-app notifications across root tenant users)
  • Infrastructure: AWS S3, Render

CarnavalRio

Schedule, samba schools, and public voting guide for Rio Carnival.

  • Android
  • iOS
  • 500+ downloads on Google Play

The Problem

Anyone seeking Rio Carnival details lacked a centralized, reliable platform. CarnavalRio consolidates schedules, samba school profiles, public voting polls, and Sambadrome venue maps into a unified mobile application.

My Role

Tech lead and sole senior developer at the startup. Architected the mobile application and API, owning all technical decisions. Team comprised 3 developers: myself and two backend interns.

Mobile app: Complete design and implementation (Expo/React Native, 24 screens).

API: Complete architecture; implemented authentication, voting engines, and asynchronous Celery tasks. Mentored interns implementing endpoints.

Migration: Planned strategy and task delegation, executing all final PR reviews and Render deployment pipelines.

Technical Decisions

Zero-downtime incremental migration in production

First migrated relational data to the new API architecture. The mobile app was then repointed to the new endpoints: new installs and updates consumed the new API seamlessly, with subsequent features rolled out in iterative updates.

Cost: Required maintaining backward compatibility for legacy app versions temporarily.

Database-enforced vote integrity

Duplicate votes are rejected via PostgreSQL unique constraints rather than application-layer checks, guaranteeing integrity even under concurrent traffic spikes. Batch voting requires verified accounts, automatically redirecting unverified users to account activation.

Real-time leaderboard using Redis ZSET

Votes are committed to PostgreSQL as the persistent source of truth before updating the Redis ZSET leaderboard. In the event of cache eviction, the ranking is deterministically rebuilt from database transactions.

Trade-off: Brief eventual consistency window between Postgres transaction commit and Redis leaderboard update.

OTP registration without persistent user creation prior to validation

Pending verification payloads reside in Redis with TTL and convert to PostgreSQL user records only upon OTP verification. Eliminates orphan accounts and minimizes persisted personal data.

Cost: Dependency on Redis availability for registration; expired sessions require restart.

Three-tier OTP throttling + centralized app HTTP error handling

Multi-level throttling mitigates brute-force abuse and SMS gateway costs. The app handles HTTP 429 by displaying the exact unlock countdown (retry_after), while HTTP 403 on voting routes to account activation.

Trade-off: Tighter coupling between network interceptor layers and navigation state.

Direct S3 uploads via presigned URLs and image normalization

Media uploads transfer directly from client to AWS S3, bypassing Django workers to conserve backend resources. Uploaded assets undergo asynchronous normalization to defend against decompression bombs.

Trade-off: Media validation occurs asynchronously post-upload.

Axios token renewal queue

Under concurrent requests with an expired session token, an interceptor queue limits refresh execution to a single dispatch while queuing parallel requests.

Cost: Race-condition-sensitive interceptor logic, pending automated frontend tests.

SecureStore credentials (Keychain / Keystore)

Authentication credentials reside in OS-level hardware-backed secure storage rather than plaintext AsyncStorage.

Cost: Asynchronous startup hydration; the app resolves session state before routing initial screens.

Expo Router and TanStack Query

File-based filesystem routing paired with declarative server cache revalidation. Client UI state is managed in Zustand.

Result

Published on Google Play Store and Apple App Store, with 500+ downloads on Google Play.

Quality: 271 automated backend tests with continuous integration running on every push.

Stack

  • Mobile App: Expo SDK 57, React Native, TypeScript, Expo Router, TanStack Query, Zustand, Axios
  • Backend: Django 6, Django REST Framework, PostgreSQL, Celery, Redis
  • Infra & Services: AWS S3, Render, Google Maps, GitHub Actions

ClickCidadão

Municipal services, public transit, and local business discovery platform.

  • App Store
  • Play Store
  • Public procurement bidding in progress

The Problem

Citizens face friction accessing municipal service information and filing civil complaints to correct administrative departments. ClickCidadão consolidates services, public transit routes, and local commerce into a single app, dispatching demands directly via email to relevant municipal secretariats.

My Role

Tech lead and sole senior developer at the startup. Architected the entire system, technology stack, and implementation workflows, directing two backend interns.

Frontend: ~90% of the codebase (React Native/Expo) and 100% since May 2026 following previous contract completion.

Backend (Django/DRF): Architecture design, PR reviews, and core service implementation.

Technical Decisions

S3 upload detached from database transaction

File transfers execute prior to database transaction commits, preventing PostgreSQL connections from lingering during slow network uploads. Failed transactions trigger cleanup hooks.

Trade-off: Atomicity trade-off; uncommitted files require Celery garbage collection jobs.

Two-tier cache for AI inference queries

In-memory + local device storage with a 15-minute TTL keyed per user. Reduces third-party LLM API expenditure and caps repeated queries. Drops response latency from 10–60s down to instantaneous on repeats.

Trade-off: Cache resides on-device; cannot be shared across devices and may serve data up to 15m old.

Transit AI assistant proxied via backend

API keys never expose to the client; authenticated user identity injects at the server level for auditing and rate-limiting.

Trade-off: Additional network hop and backend resource consumption on streaming responses.

Concurrent token refresh queue with Axios

Screens issuing parallel HTTP queries prevent session drops on token expiration. The queue ensures a single refresh call while pending requests wait and adopt the new bearer token.

Trade-off: Complex interceptor state logic, pending automated frontend tests.

SecureStore token persistence (Keychain / Keystore)

Tokens are saved directly to hardware-backed secure storage rather than standard AsyncStorage.

Auditable transactional email dispatch

Complaints route through internal SMTP servers with citizen CC and administrative audit BCC, providing delivery proofs without persisting complaint text in an internal database.

Trade-off: Absence of structured analytics database; query analysis relies on mail logs.

Result

Published on App Store and Google Play Store for iOS and Android, currently offered to municipal governments under public bidding procurement. App has zero active consumer production users.

Quality: 293 automated tests validating backend API endpoints. Frontend enforces strict TypeScript type safety and linting. CI/CD runs on GitHub Actions, with frontend OTA hotfixes delivered via EAS.

Stack

  • Frontend: React Native 0.83, Expo SDK 55, Expo Router, TypeScript, Axios
  • Backend: Django 6, Django REST Framework, PostgreSQL 16, Celery, Redis
  • Infra & Services: AWS S3, Render, Google Maps, Resend, GitHub Actions, EAS (build and OTA)
